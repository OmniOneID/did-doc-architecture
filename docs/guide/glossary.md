## 1. Overview

This document collects the terms defined in the terminology sections of the OpenDID documents.
The terms are grouped by the document in which they are defined, and the same term may be described differently depending on the context of each document.
The context in which each term is used can be found in the source document of each section.

## 2. Wallet Token

Source: [Wallet Token](./../concepts/token.md#wallet-token-terminology)

| Term | Description |
| ---- | ----------- |
| Wallet Token Seed | An initial seed value generated by the wallet and delivered to the app. |
| Wallet Token Data | Data generated by the CApp service and delivered to the app, based on the WalletTokenSeed. This is the primary data for generating the Wallet Token. |
| Nonce | A one-time value generated by the wallet, used in combination with WalletTokenData to generate the Wallet Token. |
| Wallet Token | A token granting access to the wallet, used by the app to interact with the wallet. |

## 3. Server Token

Source: [Server Token](./../concepts/token.md#server-token-terminology)

| Term | Description |
| ---- | ----------- |
| Signed Wallet Info | Signed wallet information provided by the wallet to the CApp, used by TA to verify the wallet. |
| Attested App Info | Certified app information provided by the CApp service to the CApp, used by TA to verify the CApp. |
| Server Token Seed | Initial seed value generated by the CApp and delivered to TA, serving as the basis for creating ServerTokenData. |
| Server Token Data | Data generated by TA and delivered to the CApp, based on the ServerTokenSeed. This is the primary data for generating the Server Token. |
| IV | Initialization Vector used in the encryption process. |
| Session Key | Session key between TA and the CApp, exchanged before the server token issuance. |
| Server Token | A token granting access to the server, used by the CApp to interact with the server. |

## 4. OID4VCI Issuance

Source: [OID4VCI Issuance](./../concepts/OID4VCI%20Issuance.md#12-terminology)

| Term | Description |
| ---- | ----------- |
| Credential Issuer | The entity that issues OID4VCI Credentials. In OpenDID, the Issuer server performs this role. |
| Authorization Server | The OAuth 2.0 authorization server that issues Access Tokens. It is built into the OpenDID Issuer server. |
| Credential Offer | Information that the Credential Issuer delivers to the wallet to initiate issuance. It contains the Credential to be issued and the authorization method (grant). |
| Credential Configuration | A configuration that defines the format, identifier, display information, etc. of the Credential to be issued. It is published through `credential_configurations_supported` in the Issuer Metadata. |
| Pre-Authorized Code | A one-time authorization code issued by the Credential Issuer after user authentication has been completed in advance |
| tx_code | A transaction code (PIN) used together with the Pre-Authorized Code. It is delivered to the user through a separate channel. |
| c_nonce | A one-time nonce issued by the Credential Issuer to prevent reuse of the Proof in a Credential request |
| Proof | A JWT signed by the wallet with the Holder key to prove possession of the key |
| Token Status List | A list that publishes the status of Credentials as a bit array ([TOKEN-STATUS]) |
| List Provider | A provider that manages the list of OID4VCI Issuers and provides it to wallets. In OpenDID, TAS performs this role. |

## 5. OID4VP Presentation

Source: [OID4VP Presentation](./../concepts/OID4VP%20Presentation.md#12-terminology)

| Term | Description |
| ---- | ----------- |
| Verifier | The entity that requests, receives, and verifies VPs. In OpenDID, the Verifier server performs this role. |
| Authorization Request | The information with which the verifier requests a presentation from the wallet. It contains the Credentials to present and the response method. |
| Request Object | A JWT signed by the verifier that contains the Authorization Request |
| `request_uri` | The URI from which the wallet retrieves the Request Object |
| DCQL | Digital Credentials Query Language. The query language that specifies the Credentials and Claims to present ([OID4VP]) |
| VP Token | The Credential presentation data that the wallet submits to the verifier |
| KB-JWT | Key Binding JWT. A JWT signed with the Holder key to prove key possession when presenting an SD-JWT VC ([SD-JWT-VC]) |
| DeviceResponse | mdoc presentation data ([ISO-18013-5]) |
| `response_uri` | The verifier URI to which the wallet sends the VP Token |

## 6. mdoc Proximity Presentation

Source: [mdoc Proximity Presentation](./../concepts/mdoc%20Proximity%20Presentation.md#12-terminology)

| Term | Description |
| ---- | ----------- |
| mdoc | A Credential in the mobile document format defined in ISO/IEC 18013-5 ([MDOC-FORMAT]) |
| mdoc reader | An app that requests and verifies an mdoc through proximity presentation |
| Holder | The wallet that stores and presents an mdoc |
| Device Engagement | The step in which the holder and the mdoc reader exchange connection methods and session key exchange information |
| Handover | A method of delivering Device Engagement information over NFC. There are static and negotiated handovers. |
| SessionTranscript | Data that identifies the session. It is used to derive the session keys and to sign DeviceAuth. |
| DeviceRequest | The documents (docType) and data elements requested by the mdoc reader |
| DeviceResponse | The mdoc data presented by the holder |
| issuerAuth | The issuer's signature on the mdoc |
| DeviceAuth | The value with which the holder authenticates the DeviceResponse using the device key |

## 7. SD-JWT VC

Source: [SD-JWT VC](./../data%20standard/oid4vc%20credential%20format/SD-JWT%20VC%20format.md#12-terminology)

| Term | Description |
| ---- | ----------- |
| SD-JWT VC | A VC composed of an Issuer-signed JWT and Disclosures that supports selective disclosure per claim |
| Issuer-signed JWT | The JWT signed by the Issuer. It contains the Issuer-signed claims and the list of Disclosure digests. |
| Disclosure | A string containing the salt, claim name, and claim value of one selectively disclosable claim |
| Digest | The hash of a Disclosure. It is included in `_sd` of the Issuer-signed JWT. |
| Issuer-signed claim | A claim included as-is in the Issuer-signed JWT and always disclosed. The Holder cannot omit it when presenting. |
| Selectively disclosable claim | A claim delivered as a Disclosure, which the Holder chooses whether to disclose when presenting |
| Holder binding | Binding the Credential to a Holder key. The Holder public key is included in the `cnf` claim. |
| KB-JWT | Key Binding JWT. A JWT that the Holder signs with the bound key at presentation to prove key possession |
